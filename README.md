# RWKV Discord Daily Brief

每天自动读取 RWKV Discord 中 Bot 有权限查看的活跃文字频道，生成面向 RWKV 架构团队的中文简报，并发布到本 GitHub 私有仓库。

## 日报结构

1. 总览 Brief
2. RWKV 官方发布与作者动态
3. RWKV 技术相关讨论
4. Bug 与问题
5. 社区反馈
6. General
7. RWKV 待跟进问题

日报先按与 RWKV 的相关性分级：直接相关内容进入正文，明确具有 RWKV 迁移价值的外围技术进入 General，无明确关系的内容过滤。重点关注开发者的技术意见、待回答问题、文档与工具需求。每个实质性结论必须附 Discord 原消息链接，方便人工核验。

总览固定展示过去 24 小时有更新的频道，以及本期新增和 7 日内累计待跟进问题数量。“RWKV 官方发布与作者动态”仅收录 BlinkDL 的正式发布、明确预告和重要项目说明；普通答疑仍归入相应技术分类。

完整 To-Do List 放在日报末尾，每项注明提问时间，不自动指定负责人。未得到明确答复的问题会在后续日报继续提醒，最多保留 7 天。

## 自动运行方式

GitHub Actions 每天北京时间 08:00 运行：

1. 使用只读 Discord Bot API 抓取前一天 00:00–24:00 的消息；
2. 自动忽略公告、规则、只读频道和当天没有消息的频道；
3. 使用 DeepSeek API 生成简报；
4. 仅提交 `reports/YYYY-MM-DD.md`，不上传原始聊天记录；
5. 创建同日期 GitHub Issue，方便团队成员订阅和讨论。

也可以在 GitHub 的 Actions 页面手动运行，并指定需要补跑的日期。

## 失败保护

- 中转站返回空内容或临时网络错误时，自动重试 2 次，并逐步延长等待时间；
- Chat Completions 的流式输出连续失败时，最后一次自动改用非流式请求；
- 消息较多时按长度分批分析，再合并去重，确保采集到的消息不会因输入上限被直接省略；
- AI 接口、密钥或输出格式异常时，仍发布带“降级说明”的规则版日报，避免整日缺报；
- Actions 日志只记录尝试次数、耗时、批次数和响应字数，不记录 API Key、提示词或 Discord 原文。
